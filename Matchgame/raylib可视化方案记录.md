# 消消乐 raylib 可视化方案记录

记录日期：2026-10-12。

本文记录后续可视化版本的建议方案，供稍后继续讨论。raylib 是推荐选项，尚未作为最终技术方案确认；本次只记录文档，不安装依赖或编写图形程序。

## 1. 项目位置与技术方案

- 开发语言：沿用 C。
- 开发环境：Windows、Visual Studio 2022。
- 推荐图形库：raylib，提供窗口创建、绘图、鼠标和键盘输入等功能。
- 后续图形程序位置：同级 `Matchgamevisual/` 文件夹。
- 当前 `Matchgame/` 保留命令行版本，供对照学习和复用游戏规则。
- 两个项目由父目录 `programming-course-assignment/` 的同一个 Git 仓库管理，未来统一上传 GitHub。

选择 raylib 的主要原因是它支持 C，适合通过较少的窗口与绘图代码完成棋盘显示和玩家操作。使用前需要配置头文件、库及 VS2022 链接选项，具体配置在开始实施时确定。

参考：[raylib 官方介绍](https://www.raylib.com/)、[官方 API 速查表](https://www.raylib.com/cheatsheet/cheatsheet.html)。

## 2. 界面建议

第一版建议使用“彩色方块＋数字”，无需先准备图片素材。数字继续对应原有的九种物品，不仅依靠颜色区分。

- 棋盘区域：显示 20 行、30 列的格子。
- 信息区域：显示昵称、消除长度 k、累计分数、当前关卡、目标分数和用时。
- 操作提示区域：显示选择状态、无效交换、过关和胜利等提示。
- 选中格子：使用明显边框标示。

棋盘与信息区的位置、窗口尺寸和颜色在后续设计时确定。这些界面建议尚未作为最终布局确认。

## 3. 鼠标交互建议

建议以“单击两个相邻格子交换”作为第一版操作方式：

1. 单击一个格子，将其设为选中状态。
2. 再次单击同一个格子，取消选中。
3. 单击其他不相邻格子，将选中位置切换到新格子。
4. 单击相邻格子，尝试交换两个物品。
5. 没有产生有效消除时恢复原状，并显示提示。
6. 有效交换后完成消除、计分、下落、补充及连锁，再接受下一次交换。

单击棋盘外不应触发交换。处理交换和消除期间应避免新的交换输入修改棋盘。

上述细节为后续讨论的建议，并非已经确认的操作规则。拖拽交换、WASD 辅助操作等功能暂不纳入第一版建议范围。

## 4. 游戏规则沿用范围

以已有命令行版本为基础：

- 棋盘使用二维数组保存，物品编号为 1～9。
- k 支持 3、4、5；横向或纵向连续数量达到 k 时消除整串。
- 初始化棋盘不产生可立即消除的连续段。
- 每消除一个物品获得 10 分，交叉位置只计一次。
- 消除后执行重力下落与随机补充，自动处理连锁。
- 统计整局累计用时。
- 累计达到 300、700 分分别进入后续关卡，达到 1200 分获胜。

开始复用前，应重新核对命令行版本的连续段判定、输入处理及关卡逻辑，确保图形版本以正确规则为基础。

## 5. 程序职责建议

图形版本应将游戏规则与绘图、输入分开。后续文件划分仍优先保持简单，具体结构在正式设计时确认。

- 游戏规则：棋盘生成、相邻交换、连续段检测、消除计分、重力、补充、关卡判断。
- 图形界面：绘制棋盘和信息，将鼠标位置转换为行列坐标，管理选中位置与提示。
- 主循环：读取输入、更新游戏状态、绘制当前界面。

已有 `displayGame()` 的控制台输出应由图形绘制替代；连锁中的 `printf()` 提示应改由界面展示。规则函数应避免直接依赖绘图库。

若先实现无动画版本，一次操作可以完成全部连锁后显示最终棋盘。若后续需要逐轮展示消除、下落和补充，应拆分处理阶段并按帧更新，避免通过长时间阻塞等待实现动画。

## 6. 后续推进顺序

1. 确认图形技术方案，以及首版是否展示过程动画。

3. 完成设计文档和逐步实施计划。
4. 在 `Matchgamevisual/` 配置 VS2022 工程与 raylib。
5. 实现窗口和静态棋盘，再连接交换与游戏规则。

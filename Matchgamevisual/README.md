## 环境与运行

使用 TypeScript、Phaser 4、Vite 与 Vitest。Node 支持 22.12+（22.x）或 24+，本机验证环境为 Node 24.14.1、npm 11.11.0。依赖版本由 `package.json` 和 `package-lock.json` 固定。

```powershell
Set-Location 'E:\AI\programming-course-assignment\Matchgamevisual'
npm ci
npm run dev
```

打开终端显示的本地地址，输入昵称并选择k=3/4后开始。点击格子选中，再点同格取消；点击非相邻格切换选择，点击相邻格执行交换。没有匹配时会交换回退，有匹配时依次高亮、消除、下落、补充并继续连锁。动画期间锁定棋盘输入。

三关目标为累计300、700、1200分，完整连锁结束后判定换关或胜利。暂停和切到后台时停止计时与动画，返回页面后点击“继续游戏”；正常操作与动画均计入时间。完整回合提交后若无有效交换，会提示并自动重新生成可玩棋盘，保留分数、关卡、昵称、k、用时及演示偏好。重开保留昵称和k，分数与时间归零；未完成消除回合时退出只保留此前成绩，洗牌中退出则保留刚完成回合的得分。

按H或点击“提示（H）”免费获得一个有效交换的坐标、方向和蓝色两格高亮；提示不交换、不计分，也不消费随机数。同一棋盘按固定顺序返回相同操作。下一次棋盘点击清除高亮；提示会先清除半次选择，让玩家重新点击两格执行。动画、洗牌、暂停及结束时禁用提示，文字输入、选择框、组合键和按住H的重复事件不触发提示。

开始游戏后勾选“算法演示”，可选择正常1×、慢速0.5×、很慢0.25×。桌面端说明栏位于棋盘右侧，开启演示与普通模式采用相同棋盘尺寸；空间不足时说明栏换到下方。说明栏依次显示交换、匹配、消除、下落、补充与再次检测，并展示真实匹配段、去重格数和最近一次消除的轮次、每格分值及增量。末尾空检测不会虚增CHAIN，下一次交换会清空旧摘要。设置从下一步骤生效；关闭演示恢复普通时长并保留选中的演示速度。重新开始也保留播放偏好。

演示1×将匹配高亮延长至650ms、空检测300ms，并在真实消除后保留450ms空格，便于暂停观察。0.5×和0.25×对位移、爆炸、落地和观察等待一起减速；普通模式保持原动画时长。所有模式共用真实算法步骤和终态，演示播放期间仍累计时间，暂停与后台时间不计入。

```powershell
npm run typecheck
npm run test
npm run build
npm run preview
```

test 在 Node 环境执行核心、坐标、播放、会话计时、控制器、效果及演示契约回归测试，无需浏览器。当前122项通过。build 会先执行类型检查，再生成 `dist/` 静态产物；通过 `--emptyOutDir false` 保留旧文件，避免构建时自动清理。旧哈希产物不被新页面引用，如需清理须逐文件征得用户同意。Phaser带来约1.40MB的JavaScript主包（gzip约369KB），构建仍有大分块提示。

## 独立核心接口

- `src/core/types.ts`：棋盘、物品编号、游戏状态和步骤联合类型。
- `src/core/board.ts`：约束初始化、有限重试与可玩图案兜底、重力及随机补充。
- `src/core/moves.ts`：在副本上模拟相邻交换并恢复，复用匹配扫描检查受影响行列。
- `src/core/match.ts`：横纵完整连续段扫描与位置去重。
- `src/core/game.ts`：创建游戏、完整回合结算、计分、关卡、只读提示及保留元数据的洗牌。
- `tests/core.test.ts`：固定棋盘、可复现随机序列和步骤重放契约。

TypeScript 页面控制器调用方式：

```typescript
import { createGame, resolveMove } from './core/game';

const state = createGame('玩家', 3);
const result = resolveMove(state, { row: 0, col: 0 }, { row: 0, col: 1 });
// 按序播放 result.steps，全部完成后再提交 result.finalState。
```

两个接口都可传入返回 `[0,1)` 的随机数函数。基础createBoard与补充按行优先遍历，每个生成格消耗一次随机数；初始化从合法候选中选择，补充直接在1～9中选择并允许连锁。可玩生成器最多尝试三张棋盘，失败后用两种不同物品植入保证交换的图案；固定图案格不消费候选随机数，选择两种物品消费两次。丢弃候选不发布编号，补充、换关及洗牌的可见物品编号持续递增。

`findLegalMove(state)`返回首个有效交换或null，不修改状态或消费随机数；`hasLegalMove`共用该接口。`reshuffleGame(state, random)`返回冻结的新棋盘并保留游戏元数据，拒绝已获胜状态。稳定输入的新匹配只可能出现在交换格所在行列，因此查找复用findMatches扫描这些完整行列；完整回合结算仍扫描全盘。

`resolveMove` 区分 `rejected`（非法请求或游戏已结束）、`invalid`（交换后无匹配，已生成回退步骤）、`valid`（完成连锁）。输入状态不被修改；每步带独立且冻结的 `after` 快照，CLEAR 带当轮每格分值和得分增量，GRAVITY 带物品编号及真实起终点。

异常随机源或超过100轮的持续连锁会明确抛错，不返回未稳定的伪终态；调用方保留上一稳定局面。注入的随机源可能已消费数值，错误后不能直接假设随机流也已回退。正常完成时最后一步快照与最终状态一致。

## 页面与动画接口

- `src/app.ts`：协调已提交终态与当前播放快照，管理操作锁、页面状态、暂停、取消和故障恢复。
- `src/presentation/StepPlayer.ts`：串行等待动画完成；取消信号和会话编号阻止旧步骤回写。
- `src/presentation/playback.ts`：校验演示偏好并生成独立步骤时长，不进入核心规则。
- `src/presentation/explanation.ts`：从真实步骤生成阶段说明，计分摘要由控制器读取CLEAR记录。
- `src/presentation/BoardScene.ts`：按物品id执行步骤，每步完成后检查数量、种类与位置是否对应`after`快照。
- `src/presentation/effectPlan.ts`：从真实匹配段和消除记录选择效果中心，去重并限制装饰密度。
- `src/presentation/Effects.ts`：管理共享纹理和装饰批次，Tween仍交给棋盘的步骤生命周期。
- `src/session.ts`：独立会话时钟，可注入时间函数验证暂停与累计口径。
- `src/ui/page.ts`：原生DOM页面和状态栏，将按钮意图交给控制器。

匹配高亮、得分提示和中间空格来自真实步骤。播放器完成每步后才发布该步快照，整回合全部播放完再提交终态。洗牌作为第二段独立SHUFFLE队列，先显示旧棋盘与提示，再淡出并按after重建、淡入；步骤结束检查id、kind、位置、alpha及大小。普通提示观察500ms、演示1000ms，淡出和淡入各140ms，统一采用本步倍率。跨队列仍保留暂停。故障恢复最近已提交棋盘并停止计时；洗牌故障不回退刚完成回合的成绩。

**目标：** 按课程规则与已确认的连锁计分调整，用轻量 Web 游戏真实展示消除算法的阶段状态。

**架构：** 独立 TypeScript 核心输出步骤和状态快照；Phaser 负责棋盘与动画；HTML/CSS 负责页面。一个应用控制器协调输入、播放、暂停和状态提交。

**技术栈：** TypeScript、Phaser 4、Vite、Vitest、原生 HTML/CSS。无 React、后端、数据库、物理引擎或通用事件总线。

### 核对后的规则

棋盘为 20 行 × 30 列，物品 1～9；首版支持 k=3/4，k=5 暂不开放。初始棋盘不含匹配；上下左右相邻交换，不能形成匹配则回退。连续长度不少于 k 时整段消除，交叉格只计一次。

2026-10-12 已确认调整：同一次有效交换，第 1 轮每格 10 分、第 2 轮每格 20 分、第 3 轮及以后每格 30 分；得分为去重格数乘以当轮每格分值。每次新交换重置轮次。第 2 轮及后续连锁可播放轻量爆炸效果，只作用于真实消除位置，不额外消除周围格子。其他规则变化不提前实现，不引入插件化规则系统；`PROJECT_BRIEF.md` 已同步该调整。

补充与初始化不同：初始化避免匹配，补充允许匹配，以保留连锁。一次操作全部连锁结束后才检查 300、700、1200 分门槛。C 版 `updateLevel` 使用连续的三个判断，一次操作可跨多个门槛：例如从第一关直接累计到 800 分，进入第三关且只生成一次新棋盘；直接达到 1200 分则获胜，不生成无意义的新棋盘。Web 版保留这一行为。

用户已确认的计时口径：主动暂停和切到后台时停止计时；正常操作和动画播放期间累计。关卡切换保留累计分数、昵称、k 和用时。此处是 Web 版已确认的行为，区别于 C 版从 `startTime` 连续计算经过时间。

## 2. 技术路线评估

推荐 TypeScript + Phaser 4 + Vite。TypeScript 适合约束步骤数据；Phaser 的输入和 Tween 满足交换、消除、下落需求；Vite 负责开发与静态构建。600 格棋盘首版无需 Worker、ECS、对象池或 GPU 专用批处理。

核验日期：2026-10-12。Phaser 4 已正式发布，官方 4.0.0 更新记录说明其重建了 WebGL 渲染器，Canvas 渲染器仍存在但已弃用。选择 WebGL 和基础 Sprite/Tween，避免照搬 Phaser 3 的管线、FX、Mask 示例。进入编码时选定正式 4.x 小版本并锁定依赖，不跟随浮动 latest。

本机 Node v24.14.1、npm 11.11.0；满足当前 Vite 文档的 Node 版本要求，实际包组合仍需在工程冒烟阶段验证。Vite 不做 TypeScript 类型检查，构建必须包含 `tsc --noEmit`。

备选与取舍：

| 方案 | 代价与适用性 |
| --- | --- |
| TypeScript + Phaser 4 + Vite（推荐） | 贴合定位；只使用基础 API，将版本影响限制在表现层 |
| TypeScript + 原生 Canvas + Vite | 依赖更少，但需自行维护输入、动画调度与对象管理，不利于本项目节省开发工作 |
| TypeScript + Phaser 3 + Vite | 可作为明确的兼容性阻塞出现后的替代；偏离指定技术路线，须先说明并获得用户确认 |

## 4. 核心算法与动画的数据接口

### 4.1 选择完整步骤序列与逐步快照

对一次操作，核心在棋盘副本上执行真实算法，边执行边记录每个阶段，返回 `MoveResolution`：操作结果（非法/无效/有效）、步骤数组、最终游戏状态。调用不修改输入棋盘。随机数通过函数参数注入，测试可控制补充序列。

这允许一次计算完成，也允许表现层随后慢速播放。真实性来自算法执行时生成的记录，而不是计算与动画必须同步耗时。不能只返回最终棋盘后在表现层猜测消除和下落过程。

不选纯变化补丁：省内存，但漏一条变化就可能永久偏离。也不选由动画回调驱动核心执行的生成器：暂停、退出、测试和图形生命周期会更紧密地耦合。600 格阶段快照的成本值得换取可检查性；只保留当前回合的记录，完成后释放，不构建历史回放系统。

### 4.2 状态与步骤字段

- `Position`：`row`、`col`，统一从 0 开始。
- `Tile`：只读 `id` 和 `kind`（1～9）。编号在一局中递增，交换和下落保持 id，补充及换关生成新 id。
- `Board`：20×30 的二维数组，元素为 `Tile` 或 `null`；null 表示消除后的空格。只保留这一份棋盘结构，不同时维护独立数字矩阵和编号矩阵。
- `Snapshot`：只读棋盘、累计分数、关卡与游戏结果状态。
- 每个步骤有 `index`、`kind`、`after`；`after` 是本步骤完成后的快照，前态为初始状态或上一步快照。
- 使用按 `kind` 区分的 TypeScript 联合类型，具体字段仅出现在对应步骤，不采用大量可选字段的大对象。

| 步骤 | 算法提供的变化信息 | 播放结果 |
| --- | --- | --- |
| `SWAP` | 两物品 id 与各自 from/to | 两个现有对象移动到交换后的格子 |
| `MATCH` | 本轮 round、横纵完整匹配段、去重 cells | 高亮真实匹配；棋盘和分数不变；允许结果为空 |
| `SWAP_BACK` | 两物品的反向 from/to | 无效交换恢复物品身份、位置与原分数 |
| `CLEAR` | round、去重物品 id/位置、count、scorePerTile、scoreDelta | 这些物品消失；after 中对应格为 null，分数增加 count×scorePerTile；每格分值由核心根据轮次确定为10/20/30 |
| `GRAVITY` | 所有实际移动物品的 id、from/to | 同一步并行下落，保持列内顺序；after 顶部仍为空 |
| `REFILL` | 新物品 id/kind 与目标格 | 只生成算法给出的物品；after 棋盘填满，可能仍有匹配 |
| `STABLE` | 检测已无匹配的快照 | 本回合消除结束，尚未提前重新开放输入 |
| `LEVEL_CHANGE` | 原关卡、新关卡、新棋盘快照 | 在连锁结束后更换棋盘并更新关卡 |
| `WIN` | 最终结果快照 | 结束计时并展示胜利结果 |

补充动画的棋盘外起点属于表现层：同列顶部有 h 个空格时，目标行为 r（0≤r<h）的新物品从 r-h 行进入，保持同列次序。核心只决定真实物品和目标位置，不包含棋盘外虚拟格。

### 4.3 步骤顺序

有效操作：`SWAP → MATCH(非空) → CLEAR → GRAVITY → REFILL → MATCH … → MATCH(空) → STABLE → 可选 LEVEL_CHANGE 或 WIN`。

无效操作：`SWAP → MATCH(空) → SWAP_BACK → STABLE`，结果标记为无效；非法/越界/非相邻请求返回拒绝及空步骤，不播放交换动画。

连锁检查复用下一次 `MATCH`，无需再引入一个重复扫描的 `CASCADE_CHECK`。round=1 是首次消除，实际第二轮非空匹配才显示 `CHAIN ×2`；空匹配检查不增加连锁计数。

### 4.4 如何保证动画对应真实状态

1. 横向和纵向都扫描当前棋盘，完整收集连续段，再统一标记与消除；不边扫描边删除。每轮为 O(行×列)。
2. 重力用列内读写指针压缩，直接在移动时记录 from/to；渲染层不比较颜色猜测物品来源。id 保证相同数字的物品也不会串位。
3. 每个快照复制外层数组和各行；Tile 本身只读。记录不能引用之后会继续修改的工作数组。
4. 播放器严格串行等待步骤；同一步内的多个 Tween 并行，全部完成才推进。采用动画完成信号，不使用估算总时长的 `setTimeout`。
5. 每步开始显示阶段名，以该步前态开始动画；结束后确认对象 id、kind、格子位置与 after 一致，再发布对应 HUD 快照。CLEAR 的分数在实际消除完成后显示，不提前显示本回合最终分数。
6. 控制器在计算前锁输入，仅在整条记录播放结束且会话仍有效时提交 finalState。逻辑最终状态不等于正在播放的可见中间状态；玩家可见状态由步骤快照驱动，属于只读展示数据。
7. 完成后检查最后快照等于 finalState。发现不一致时停止本回合并报告错误，不静默跳到终态掩盖中间错误。
8. 暂停冻结当前 Tween 和阶段等待，并停止计时；恢复继续同一步。切后台自动暂停，回前台显示继续入口，不覆盖玩家之前的主动暂停。退出/重开取消播放，递增会话编号，旧回调不得提交状态或解锁新会话。

算法演示模式与普通模式消费相同的步骤。它只改变高亮、说明和播放速度，不改变随机数、得分或匹配规则。速度变更从下一步骤生效，避免中途改时长造成时序复杂化。首版展示真实阶段与匹配结果，不模拟逐格扫描游标。爆炸根据 CLEAR 的真实 round 和位置播放，不参与核心规则，也不承担额外计分。

## 7. 必要测试与检查

长期测试只围绕规则和接口，不通过截图判断算法正确性：

- 初始化：k=3/4，全部格有物品，id 唯一，扫描无匹配；极端固定随机返回值也能结束初始化。
- 连续段：恰好 k、超过 k、被其他值打断、空格不匹配、边界段；横纵交叉去重。例如 k=3 的十字由两条三格段组成，去重为 5 格、得分 50。
- 无效交换：完整恢复棋盘值及物品 id，分数/关卡不变；越界和非相邻操作不改变输入。
- 重力：示例列 `[1,null,2,null,3]` 变成 `[null,null,1,2,3]`，对应物品的 id 和相对顺序保留，位移记录准确。
- 连锁：注入明确补充序列触发两轮，只有两轮 CLEAR；最后 MATCH 为空，STABLE 无空位及匹配。
- 分数：同次交换4轮均消除3格时，得分依次为30、60、90、90，总计270；下一次交换第1轮仍为每格10分。交叉格按当轮每格分值只计一次。检查恰好达到门槛、跨过单个门槛、一次跨多个门槛、达到1200后停止；关卡判定晚于所有连锁步骤。
- 快照：旧步骤不会被后续修改；按变化记录重放可得到每步 after，最后快照等于 finalState。
- 播放：使用可控的假动画完成信号验证前一步未完成时不启动下一步、每步只发布一次、取消后不再提交；暂停与重开隔离用同样的契约检查。
- 计时：应用计时函数以可注入时钟测试，正常与动画累计，暂停/后台排除，换关保留，胜利/退出冻结。
- 无有效交换：稳定棋盘可正确报告不存在合法操作，不自动改变棋盘或计分。

保留项目正式的 Vitest 回归测试，不创建一次性测试脚本。阶段 A 已执行核心回归测试，没有生成临时测试脚本。后续若产生临时脚本，遵守用户的逐文件删除与事前同意要求，不批量清理。

## 8. 风险与设计取舍

| 风险 | 处理与取舍 |
| --- | --- |
| Phaser 4 资料与旧示例混用 | 优先版本对应文档与正式包；先做基础绘制/Tween 冒烟，不开发自定义渲染管线 |
| 600 格导致数字过小、对象较多 | 数字纹理或复用 Sprite，整体缩放，突出选择；不承诺小手机适配，不提前做对象池 |
| 动画期间旧回调污染新局 | 单队列、操作锁、会话编号、显式取消；分数和终态只有一个提交入口 |
| 快照浅拷贝被后续算法改写 | 复制每行，只读物品；用旧快照与重放契约测试直接验证 |
| 无初始匹配不代表存在有效交换 | 用户后续已批准并实现可用操作检测、有限重试与可玩图案兜底、自动重新生成棋盘。仅保证新棋盘至少有一个有效交换；再次死局仍自动洗牌，保留已提交成绩及计时 |
| 补充随机数导致难复现或极长连锁 | 注入固定序列/种子；补充不禁止匹配。增加显式故障保护，触发时中止并报告异常，不能把未稳定棋盘标成 STABLE 或静默截断连锁 |
| 换关发生过早或越级行为变化 | 所有连锁完成后由核心统一判定；跨门槛直接进入最终关卡，一次换盘 |
| 展示速度影响用时 | 用户已选择动画计入累计时间；本项目无排行榜，不另定义成绩比较或扣除演示耗时 |
| 连锁加分加快过关 | 保留300/700/1200累计目标，全部连锁结束后判关；每格分值在第三轮封顶30分，爆炸不引入额外计分入口 |
| 课程注释要求与简洁维护的平衡 | 源码和注释 UTF-8；按课程要求说明变量、函数参数/返回值和关键算法，避免大量重复的逐行解释 |

故障保护在阶段 A 落实为 `MAX_CHAIN_ROUNDS=100`，持续产生第101轮匹配时显式抛错并不提交回合，不返回伪STABLE。只用于识别异常随机源或算法错误，不会因此自动洗牌、修改物品或提前结束正常计分。
